Safe to run against production

It never writes anything to Vault, and it never reads a secret value. Both are enforced in code, not by convention:

  • The scanner's Vault client can only send GET and LIST requests. Any other method is rejected inside the client before a request is built.
  • For KV secrets it reads only /metadata (version, last-updated time), never /data. Tests plant a secret value and fail if it ever shows up in any report format.
  • Our CI runs the full scan against real Vault and OpenBao servers and counts every HTTP method that actually reaches them.

It talks only to your Vault: no telemetry, no call to us or to HashiCorp. A minimal read-only Vault policy ships with it. If your token can't read something, that check is listed as "not checked" and the scan carries on.

Run it in five minutes

  1. Download keyorix-migrate for your platform (Linux or macOS, amd64 or arm64) from the GitHub releases page. It's a single binary with a signed checksum and an SBOM. The read-only policy file, healthscan-policy.hcl, is in the same repository.
  2. Create a short-lived, read-only token:
    vault policy write healthscan-readonly healthscan-policy.hcl vault token create -policy=healthscan-readonly -ttl=1h
  3. Run the scan:
    export VAULT_TOKEN=... # the token from step 2 keyorix-migrate vault scan \ --addr https://vault.example.com:8200 \ --output ./report
    You get report.html, report.md and report.json. Private CA? Add --cacert ca.pem. Vault namespaces and AppRole login are supported too.
